# STU-CORE-01 — local-only adult project persistence runbook

**Boundary, 31 October 2026:** The owner chose the existing React/Vite + Fastify + Railway PostgreSQL stack, **this first project-core slice**, and local development/testing now. A private adult staging ingress or any deployment requires **separate** approval of region, budget, law/privacy, identity, backups, security and origin design. This runbook does **not** approve it. The public Render guide is unchanged and read-only. A real **data-only JSON client** is now lazy-loaded under `/pilot/projects` in the combined adult source after an authenticated successful learner list; it is still local-only and unavailable on the public Render guide or default-off Railway API. No Scratch/GDevelop editor, executable preview, PNG upload UI, school tenancy, child account, gallery, assessed project or live AI is wired to this API.

## What is real, and what is not

The new **server-only** `/api/pilot/project-core/v1` routes persist private per-account JSON documents and sanitized PNGs in additive `project_core.*` tables. A signed-in, active, adult-self-attested `pilot.users.role=learner` owns every project. Creation writes revision 1; subsequent saves append immutable numbered revisions under a row lock and a client-supplied `baseRevisionNo` compare-and-swap. All writes require the existing exact Origin, JSON content-type, CSRF token and session; reads require the same active learner session. Another learner gets 404 rather than document or image data; reviewers get 403. The owner ID is always taken from the server session, not the request body. The schema constrains owner/project references, latest-revision existence, append-only evidence and no project reassignment/rewind; startup checks the schema checksum and enabled triggers. This is a working persistence **API** and local JSON-document client, not a licensed visual/code studio, preview or approved real-user deployment. The old course-coupled `learning.sandbox_*` evidence is distinct.

### Contract and hard limits

| Method and route (all under `/api/pilot/project-core/v1`) | Input | Successful response |
|---|---|---|
| `GET /projects` | Active adult learner session. | Up to 10 owned private project summaries; no document content. |
| `POST /projects` | `{title,document,requestId}` with a fresh UUID; title 1–120 characters, bounded JSON object. | `201` project ID + **initial** revision number 1 and SHA-256 digest; exact idempotent replay `200` with `repeated:true`. |
| `GET /projects/:projectId` | Owned project ID. | Latest immutable revision, manifest and truthful `storage-only` authority. |
| `GET /projects/:projectId/revisions/:revisionNo` | Owned project ID and 1–50. | That historical immutable revision, even if a newer one exists. |
| `POST /projects/:projectId/revisions` | `{baseRevisionNo,document,assetIds,requestId}` with only **this project's** asset UUIDs. | `201` with new revision number/digest; exact replay `200` and `repeated:true`. A stale base returns `409 REVISION_CONFLICT` **without** overwriting. |
| `POST /projects/:projectId/assets` | `{dataBase64,expectedSha256,requestId}`; exact digest of received PNG bytes. | `201` server-assigned image ID, **normalized** PNG digest/dimensions/size; exact replay `200`. This route alone allows a 144-KiB JSON body. |
| `GET /projects/:projectId/assets/:assetId` | Owned project and image IDs. | Server-verified normalized bytes with `image/png`, `attachment` and `private, no-store`. |

No update/delete, publish, export, editor import, grade, teacher, class, offline queue or user-controlled media type route exists. A project accepts at most 50 revisions and 8 uploaded PNGs; an account at most 10 projects. The JSON document is a **data-only** object, at most 16,384 serialized bytes, 384 nodes, 12 levels, 64 keys/object and 2,000 code units/string. Its keys are canonicalized, but no vendor/editor or pedagogical semantics are inferred. Image source ≤98,304 bytes, ≤1024×1024 and ≤1,048,576 pixels; CRC and full PNG decode are checked and server re-encodes RGBA with no original ancillary metadata. Normalized stored image ≤131,072 bytes. It is a restricted image intake, **not** general asset/malware safety certification. `source_sha256` is stored for same-request replay, not as a substitute for removing personally identifying image metadata. Audit events contain IDs/counts/digests, never document bodies or image bytes. No private record may affect the existing 44-course/versioned credit path.

### Recovery/error semantics

- `401` unauthenticated/disabled, `403` reviewer or invalid Origin/CSRF, `404` foreign/absent project or asset, `415` wrong mutation media type, `422` invalid document/manifest/image, `413` storage/pixel/body limit, `429` private quota/rate limit, `409 REQUEST_REUSED` when a request ID changes meaning. Do not expose another user's existence through the error copy.
- After `409 REVISION_CONFLICT`, fetch the current owned project, **compare** historical and latest documents, and decide a new save with a **new** request ID and current base. Never silently overwrite work. No merger, autosave or offline replay UI has been delivered.
- If a POST times out and commit status is unknown, resend the **same** request ID and identical payload after re-authentication. `200 repeated:true` confirms a saved prior result; a new `201` confirms this attempt committed. Do not claim success on a network error. A failed validation should preserve the caller's local content for correction without saying it saved.
- The create endpoint's replay reports **revision 1's** digest/number even if the project has advanced; GET reports actual latest state. A body digest is evidence of bytes, not a signature or a course grade.

## Disposable local operation, not a staging recipe

1. Work on Node 22 and PostgreSQL 17+, from the repository root. Create a **new, isolated, loopback-only** DB named `desloop_project_core_disposable_*`, never use a real user/shared/Railway DB. The automated test truncates **only** a URL with that name on `127.0.0.1`. Keep its connection string in the local shell/secret store, not Git, browser variables or chat.
2. To initialise a fresh test DB with existing migrations, use the normal private adult `npm run engine:migrate` on **that disposable DB only** (which installs 001–003), with `ENGINE_DRAFT_ACKNOWLEDGED=true` and a named `PILOT_OPERATOR`. This does not enrol a learner or release the candidate. Compile `npm run build:server` before any CLI command. Alternatively the integration test itself initialises 001 and 003 in its own throwaway DB; it does not activate the draft-2 engine.
3. For manual 005 installation set `NODE_ENV=test` or `development`, `HOST=127.0.0.1`, `APP_ORIGIN` to the exact loopback front-end origin, `PILOT_OPERATOR` to an identifiable **local** operator, and `PROJECT_CORE_LOCAL_MIGRATION_APPROVED=true`; run `npm run project-core:migrate`. It verifies the existing release and safeguarding hold, applies `005_project_core.sql` without deleting old tables, records the migration file SHA and a synthetic-local audit. Changed source/disabled protections fail closed. **It is not** in Railway `engine:migrate` or Render deploy config.
4. Only then may a developer test the API with `PILOT_ENABLED=true`, `PILOT_DRAFT_ACKNOWLEDGED=true`, `PROJECT_CORE_ENABLED=true`, `PROJECT_CORE_LOCAL_ACKNOWLEDGED=true`, `HOST=127.0.0.1`, `APP_ORIGIN` on `127.0.0.1` and that named disposable loopback DB. Bind only localhost, including the Vite side (`./node_modules/.bin/vite --host 127.0.0.1`, **not** the public-preview `npm run dev` 0.0.0.0 default); use synthetic adult invitations/accounts. In a local same-origin Vite browser session, an authenticated learner's successful GET adds the **Private project documents** link at `/pilot/projects`; when the server returns 404 it is hidden, and a direct URL cannot create anything. The client edits bounded JSON data only, preserves attached server image IDs on save and handles explicit 409 comparison/same-ID retry. The **later unpushed UI-02** additionally holds existing-document unsent drafts in per-account mounted-pilot memory, rechecks owner access via server GET on return, retains unknown-outcome request IDs across internal navigation and clears on sign-out/exit; it is **not** offline/durable storage or new-project form recovery. It is **not** a vendor editor, PNG upload, preview or assessment authority. The feature defaults off, including in `.railway/railway.ts`; a production/remote setting is rejected by `loadConfig` even if someone copies the opt-in flags. `PROJECT_CORE_ENABLED=false` closes all new routes with 404 without dropping records.
5. Test with `PROJECT_CORE_TEST_DATABASE_URL` pointing **only** to a separate named disposable loopback DB and `npm run test:server`. A full regression needs three *other* distinct disposable DBs for PILOT/ENGINE/AI tests. The opt-in **real browser journey** uses a **fifth different** named disposable loopback DB: after `npm run build:server`, explicitly approve `npm run engine:migrate` then `npm run project-core:migrate` with a named operator and local-only flags in steps 2–3, and set `PROJECT_CORE_E2E_DATABASE_URL` to exactly that test DB before `npm run test:e2e:project-core`. Its Playwright config starts Fastify/Vite bound to 127.0.0.1 with synthetic accounts; it refuses a remote DB and tests desktop/mobile round-trip, conflict, replay, cross-account denial, axe and 320px reflow. The workflow at GitHub `main` `5641102…` creates four regression DBs **plus this fifth browser DB** and [passed remotely](https://github.com/Dennis-deve/desloop-academy/actions/runs/41246188703). The **later local UI-02 source is not in that run** and has not been pushed. Run typecheck, lint, `npm test`, builds, public-route/browser tests and the full audit. **Never** run `TRUNCATE`, schema drops or fixture commands on live/shared data.

## What must be resolved before any separate private staging request

- Owner-approved private ingress/region/budget and technical network inventory, plus a qualified Ghana-first privacy/legal/security review; adults still need more than self-attested age for real-user processing. Child/guardian flags remain false. No public domain/proxy, cross-origin iframe or generic preview service is implied.
- Security review of parser/PNG limits, request budgets, quota/storage load, DB least-privilege runtime role distinct from migration role, backup/restore, independent tamper-evident audit, rate limiting across nodes, privacy/retention/erasure of immutable documents/images, session revocation, MFA and incident response. The application DB owner can disable triggers; local startup checks are **not** independent anti-tamper proof. There is intentionally **no deletion API** pending policy; this is a **blocker** for real personal data, not a guarantee of indefinite retention.
- Keep the required whole-dependency audit enforced. The **initial** local lockfile failed with 15 moderate dev-tool advisories; [a later verified local tooling upgrade](evidence/project-core/DEPENDENCY_REMEDIATION_2026-10-31.md) passed full and production-only low-threshold audits with **0 findings** and reran local CI/browser gates. The `5641102…` GitHub source did pass remote CI, but **UI-02 has local checks only**. Neither a local audit nor green CI is a private-runtime/staging approval; do not suppress the whole audit to force deployment.
- Choose/licence/review an actual editor/adapter, safe separate runtime origin, export format and keyboard/AT design; verify ownership and project round-trip with an actual client, representative Ghana 3G/low-RAM device, and failure/recovery UX. School tenants, teachers, minors, public sharing, offline work, arbitrary code and credit are **different later decisions/features**. No claims of WCAG 2.2 AA, accreditation or operational adult studio follow from this local API.
