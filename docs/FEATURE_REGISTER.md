## Gate procedure and evidence format

For each atomic feature: understand requirements → design primary flow/states → implement UI/logic → connect controls → persist where needed → secure auth/validation → handle loading/empty/error/retry → logic tests → integration tests → permission tests → representative usability → keyboard/focus/AT → responsive/desktop where relevant → security review → connected regression → record expected/actual and evidence → update status → only then proceed. Record test **commands, date, result, file/report, limitations** in the feature entry. If any required check fails, status `FAILED_QA` until fixed/retested. A real-provider dependency not available is `BLOCKED_EXTERNAL_DEPENDENCY`, not fake success.
