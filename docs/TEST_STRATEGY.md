# Quality assurance and acceptance strategy

Feature status is governed **only** by [FEATURE_REGISTER.md](FEATURE_REGISTER.md). For every atomic feature, record expected/actual, result, file/report, environment and gaps. A green build does not replace user, manual AT, provider or security tests.

## Required gates before `VERIFIED_COMPLETE`

Manual first-time course-search task and comprehension with representative users; keyboard-only tab/focus/skip in actual desktop/mobile browser; manual VoiceOver/NVDA/TalkBack or equivalent for route change, search count and unavailable/error; contrast, 200–400% zoom and reflow; reviewed copy/age adaptation; security review of public build/caching and real deployment smoke tests after push. Record each check with date, tester, expected/actual and screenshot/report if authorised; do not mark it passed because it is scheduled. Future payment/AI/school/offline tests must use real approved provider and tenant boundaries, not fixtures that claim live results.
