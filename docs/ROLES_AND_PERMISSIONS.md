# Roles, permissions and trust matrix

**Only the adult pilot roles below are enforced on a live backend.** Historical `Role` values in browser-only modules are local preview types, not entitlements; the release router does not expose those workspaces. No minor, school, partner, guardian or payment role can be obtained through the adult invitation endpoint.

| Actor | Read-only public course guide | Private pilot self-records | Review assigned work | Issue invites/disable adults | Child access / consent | School / payment | AI-01 admin (source-only, default-off) |
|---|---|---|---|---|---|---|---|
| Anonymous visitor | Yes (draft metadata only) | No | No | No | No | No | No |
| Invited self-attested adult `learner` | Yes | Own active draft-1 record; separately enrolled draft-2 record and private project revisions | No | No | No | No | No |
| Invited adult `reviewer` | Yes | Own account/session and assigned review queue | Assigned submissions only; audited decisions | No | No | No | No without separate membership grant |
| **Separately granted active adult `reviewer`** | Yes | Own pilot records; only synthetic private AI drafts | Assigned submissions only | No | No | No | May inspect/configure private AI models/routes/limits/health and ask for synthetic drafts. A **different** AI admin is required to approve generic explanation reuse. No curriculum publication or credit. |
| Trusted CLI operator | Not a browser role | Restricted server/DB shell actions | Assign specific reviewers, inspect pending work | One-time invites, disable accounts, migration | Cannot bypass hard-disabled gate | No | May apply separately approved migration 004 and explicitly grant an existing reviewer. No browser admin by CLI role alone. |
| Minor / guardian / teacher / school / partner / payment staff | Public guide only as visitor | No account in these roles | No | No | No | No | No |

**Enforcement:** Fastify validates requests and looks up a hashed session in PostgreSQL. Cookie role is never trusted from the browser. The unpushed AI-01 source separately checks `ai.admin_members` after active reviewer/session checks for admin reads and Origin/CSRF-protected writes; disabled members lose access. `/api/pilot/ai/drafts` is restricted to the **same granted AI reviewers**, not ordinary reviewers or a learner tutor. The feature requires explicit server flags, a private database migration and a verified approved model; no live provider exists yet. Authenticated mutations require exact Origin, CSRF header/cookie match and server-side permission; reviewer writes require assignment, attempts use idempotent IDs and transactions, and disabled sessions are rejected. `APP_ORIGIN` remains a closed placeholder on Railway, so the current private API is not browser-accessible to external testers. Public course search is static and grants nothing. Direct fake workspace URLs receive HTTP 404 on the built server and no privileged state.

**Missing boundaries:** secure account recovery/email ownership, age verification, reviewer MFA, per-device session UI, school tenant IDs/RLS, staff verification, guardian authority, granular admin roles, upload ACLs and real billing permissions. Future policies must follow deny-by-default, per-record ownership, cross-school isolation tests, audited escalation and qualified safeguarding approval. See [security risks](SECURITY_AND_PRIVACY.md) and [feature status](FEATURE_REGISTER.md).
