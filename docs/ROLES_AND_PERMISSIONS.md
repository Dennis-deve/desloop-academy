# Roles, permissions and trust matrix

**Only the adult pilot roles below are enforced by the existing private backend.** The **new project-core rows are only in a separately enabled, localhost/disposable-DB test slice**, not a deployed adult studio. Historical `Role` values in browser-only modules are local preview types, not entitlements; the release router does not expose those workspaces. No minor, school, partner, guardian or payment role can be obtained through the adult invitation endpoint.

| Actor | Read-only public guide | Private pilot self-records | Local-only project core | Review assigned work | Issue invites/disable adults | Child / school / payment | AI-01 admin (source-only) |
|---|---|---|---|---|---|---|---|
| Anonymous visitor | Draft metadata only | No | No (`401`/default-off `404`) | No | No | No | No |
| Invited self-attested adult `learner`, **active session** | Yes | Own draft-1 records; separately enrolled draft-2 record and course-coupled sandbox | When separately enabled **locally**: data-only browser client lists/creates/reopens own JSON documents, compares 409 and appends immutable revisions; the API separately allows sanitized PNG intake but this client has **no PNG upload UI**. No course credit; cannot read/change any other owner's project or image | No | No | No | No |

A **different** AI admin approves generic explanation reuse; no course credit. |

**Enforcement:** Fastify validates requests and looks up a hashed session in PostgreSQL; the cookie never conveys authoritative role. The unpushed AI-01 source separately checks `ai.admin_members` after active reviewer/session checks for admin reads and Origin/CSRF-protected writes; disabled members lose access. `/api/pilot/ai/drafts` is restricted to the same granted AI reviewers, not ordinary reviewers or a learner tutor. No live provider exists yet. Authenticated mutations require exact Origin, CSRF header/cookie match and server-side permission; reviewer writes require assignment, attempts use idempotent IDs and transactions, and disabled sessions are rejected. Project-core routes additionally require an explicit local-only flag, schema/guardian verification, owner-sourced IDs, account-scoped SQL, append-only evidence and correct image format. Tests exercise cross-account/role denial; no school-tenant model is established. `APP_ORIGIN` remains a closed placeholder on Railway; the current private API is not browser-accessible to external testers. Public search is static and grants nothing. Direct fake workspace URLs receive HTTP 404 on the built server and no privileged state.

**Missing boundaries:** secure account recovery/email ownership, age verification, reviewer MFA, per-device session UI, school tenant IDs/RLS, staff verification, guardian authority, granular admin roles, general object storage/upload ACLs, private-project retention/erasure, independent DB/audit privilege and real billing permissions. Future policies must follow deny-by-default, per-record ownership, cross-school isolation tests, audited escalation and qualified safeguarding approval.
