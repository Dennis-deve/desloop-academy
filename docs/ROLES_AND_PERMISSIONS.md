**Enforcement:** Fastify validates requests and looks up a hashed session in PostgreSQL; the cookie never conveys authoritative role. The source-only, default-off AI-01 boundary separately checks `ai.admin_members` after active reviewer/session checks for admin reads and Origin/CSRF-protected writes; disabled members lose access. `/api/pilot/ai/drafts` is restricted to the same granted AI reviewers, not ordinary reviewers or a learner tutor. No live provider exists yet. Authenticated mutations require exact Origin, CSRF header/cookie match and server-side permission; reviewer writes require assignment, attempts use idempotent IDs and transactions, and disabled sessions are rejected. Project-core routes additionally require an explicit disposable-local or D22 gated-synthetic flag, schema/guardian verification, owner-sourced IDs, account-scoped SQL, append-only evidence and correct image format. Tests exercise cross-account/role denial; no school-tenant model is established. Historical Railway source used a closed `APP_ORIGIN`, but the owner now reports that service deleted; only a separately hosted, gated Render stage could permit synthetic adult browser access. Public search is static and grants nothing. Direct fake workspace URLs receive HTTP 404 on the built server and no privileged state.

**Missing boundaries:** secure account recovery/email ownership, age verification, reviewer MFA, per-device session UI, school tenant IDs/RLS, staff verification, guardian authority, granular admin roles, general object storage/upload ACLs, private-project retention/erasure, independent DB/audit privilege and real billing permissions. Future policies must follow deny-by-default, per-record ownership, cross-school isolation tests, audited escalation and qualified safeguarding approval.
