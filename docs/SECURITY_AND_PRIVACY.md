# Security, privacy and safeguarding risk register

**No formal audit or legal opinion has been performed.** This register controls release decisions; risk ownership must be assigned before real records. Refer to [guardian hold](GUARDIAN_CONSENT_AND_IDENTITY.md) and [permission matrix](ROLES_AND_PERMISSIONS.md). Railway was last verified as domainless with synthetic-only data; recheck after the source push.

| ID / severity | Threat / evidence | Mitigation now | Unresolved release gate |
|---|---|---|---|
| R01 HIGH | Draft answer text can leak through apparently public metadata. The FND-01 build gate initially **failed** because both intended outcomes and final module focus repeated correct-option text. | Public projection now omits outcomes and focus; Python/Node tests scan long question/option/explanation strings; production JS contains no known mock workspace or assessment text. | Independent reviewed question bank, separate published outcomes/content and adversarial bundle review before credit. |
| R02 CRITICAL | A minor could be invited or guardian status falsely asserted if adult self-attestation were treated as verification. | Adult-only roles/invites; three child env flags rejected; database CHECKs hard-disable account/data/learning fields; no child evidence endpoint. | Qualified Ghana legal/privacy/safeguarding owner, proportionate age assurance, authority and scoped consent/withdrawal, trained incident response, independent review. |
| R03 HIGH | Public domain or DB TCP proxy could expose internal adult API to browsers. | Railway app/DB reported zero public domains and no `DATABASE_PUBLIC_URL`; exact closed `APP_ORIGIN`, CSRF and cookie protections; no new ingress in FND-01. | Approved private identity-aware HTTPS ingress without bypass, browser-origin/MFA/recovery tests, cost/security monitoring. |
| R04 HIGH | Browser role flags, direct URLs or localStorage could grant unearned credit or expose simulated successes. | Release entry imports neither legacy router nor mock providers, built server returns 404 for fake URLs; server authorises all adult progression. Retired SW deletes only stale static shell caches. | Replace legacy source modules with real tenant/role/provider features; never use archived simulation tests as production evidence. |
| R05 HIGH | School/student records could cross tenants. | No live school records or admin routes exposed. Adult repository checks own records and assigned reviews. | Tenant schema, scoped queries/RLS, cross-school tests and operational verification before school pilots. |
| R06 HIGH | Lost/disputed access to adult accounts; reviewer abuse. | Argon2, hashed opaque sessions, HttpOnly cookies, exact Origin/CSRF, restricted CLI and audit events. | Account recovery/email ownership, reviewer MFA, per-device revocation, distributed throttling, independent audit retention. |
| R07 HIGH | Data loss on failed migration, deployment, device loss or restore. | `engine:migrate` blocks new Railway deploy on failure; localhost PG tests are isolated. | Approved backups, restoration drill, retention/deletion, observability, incident owner and tested rollback before personal data. |
| R08 HIGH | Untrusted uploads, code execution, AI outputs or payment webhooks could compromise host or users. | None of these public functions is live; the visual engine is bounded declarative data, not arbitrary code. | Isolated runner, upload scanning/ACL, provider-signed idempotent billing, output moderation and human escalation after approval. |
| R09 MEDIUM | Static server may label unknown URLs successful or reveal stale browser shell. | `server/src/public-routes.ts` allowlists real routes and returns HTTP 404 for retired/unknown paths; `public/_redirects` now enumerates only 48 exact public guide paths, checked at build. SW/cache retirement is best effort on next online load. | Test older controlled clients offline and service-worker update behaviour before any future offline release. |
| R10 MEDIUM | Good automated axe results might be misrepresented as WCAG conformance. | Automated mobile/desktop keyboard/reflow/axe evidence recorded; status remains `IMPLEMENTED_PENDING_TESTS`. | Manual screen-reader (at least one desktop/mobile combination), zoom/contrast/task testing with representative users. |

**Operational rules:** least-privilege server-side checks, no child–adult direct chat, no public child work/profile, minimal logs and approved retention, private provider secrets, CSRF and idempotency for writes, audit without sensitive body data. The Fastify request logger redacts cookies, auth, passwords and invitations; review any new fields before logging. An application DB owner can modify current audit tables, so append-only triggers are insufficient for tamper-proof evidence. No formal DPIA, pen test, code-signing or Ghana compliance certification exists.
