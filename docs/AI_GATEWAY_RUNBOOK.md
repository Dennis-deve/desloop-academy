## Architecture and actual boundaries

- Fastify's `server/src/ai/{providers,guard,gateway,store,routes}.ts` uses a common `AIProvider.generate` contract (text, measured usage if available, selected/returned model). Credentials live **only** in server process environment/approved secret manager; no key registration, key echo, `VITE_` secret or browser model call. Six adapters: Gemini REST, GroqCloud, OpenRouter, Cloudflare Workers AI, NVIDIA NIM hosted OpenAI-compatible chat and *loopback-only* Ollama native chat. Other modalities, live tool calls, agent execution, embeddings, speech and provider file uploads are **not** included. The absence of those features is deliberate, not a simulated success.
- `004_ai_gateway.sql` is **manual and opt-in**, not part of the existing `engine:migrate` Railway pre-deploy. It adds `ai.*` tables on the private database: approved-reviewer membership, disabled model metadata, task routes, hard-zero initial budget/provider caps, atomic UTC-day user/provider/global reservations, metadata-only attempts, generated **draft** content and a seven-day human-reviewed explanation cache. It never changes `pilot.*`, `learning.*` credit or the hard-disabled `safeguarding.*` child gate. Pending requests can have uncertain provider charges after timeout/crash; they are **not** counted as success.
- `GET /api/pilot/ai/admin` and private `/pilot/ai/admin` require an existing active *adult reviewer session* plus a **separate manually granted server-side `ai.admin_members` permission**. Every mutation checks exact Origin + session + CSRF. Anonymous, learners and ordinary reviewers cannot change models, budget or routes. `/api/pilot/ai/drafts` also requires the **separate AI admin membership** (not just a reviewer role), synthetic-source acknowledgement, session, Origin and CSRF; it returns only a server-validated **unreviewed draft** or an explicit error. No learner-facing AI route is wired to progression. Admin MFA, independent security review, legal and child safeguards remain **release blockers**.
- All provider/model routes are disabled unless owner-reviewed terms, per-provider/global/user budgets, available server credentials, **real validated API verification within 30 days bound to the current credential and endpoint/upstream**, explicit enablement and task routing are present. Only a private hash of that credential/endpoint binding is stored in `ai.models`; it is never returned to the browser. Secret rotation or changed NVIDIA base/OpenRouter upstream requires a new approved real verification before routing resumes; a DB `enabled` flag alone is not availability. Gemini is hard-blocked because of the current under-18 API-client restriction; no laundering through OpenRouter. NVIDIA base URL defaults to `https://integrate.api.nvidia.com/v1` and must use an approved HTTPS host; it reads only `NVIDIA_API_KEY`. Exact supported model IDs/capabilities are **administrator records**, not fallback guesses. No model is pre-installed/enabled.
- Plain-text reviewer input is bounded, common PII/credential patterns are denied, no pilot ID, email, sessions, school, guardian or raw assessment answers are attached to external requests. Vendor input is wrapped as untrusted JSON data below a fixed task/policy system instruction; model tools, web browsing and executions are absent. Output requires one final complete text response, exact model ID, no refusal/tool invocation/reasoning trace and server-side draft checks. **These measures do not prove immunity to prompt injection, PII leakage, bias, incorrect answers or child safety**: restrict to fictional/synthetic adult reviewer material until qualified manual safety/quality review. AI output never authorises course unlocks, grading or content publication.
- Retries (`AI_RETRIES=0..2`) use jittered exponential backoff and `Retry-After` where short; each retry and fallback reserves **another** budget/attempt atomically before contacting a model. 429 and timeout are recorded without provider body. Per-attempt timeout (`AI_TIMEOUT_MS` 1–30s), cooldown, last observed health, attempt/tokens/cost estimates and 80% provider/global plus identity-free per-user peak quota alerts appear in the private UI. A provider 429 or outage can fall back **only** to another separately approved route/credential/capability. If none works, return `AI_UNAVAILABLE`; never return mock text. A timed-out request can still be billable; reconciliation is mandatory. The application reserves conservatively, not a guarantee of provider invoice/spend hard-stop: set **provider-side** spend limits as well.
- Generated prompts/output are retained in restricted `ai.drafts` for a default *logical* 30-day window; expired items stop being returned but **physical deletion/erasure automation is not implemented**. Only a different authorised AI admin can review a generic explanation for temporary *internal reuse*; this is neither published curriculum nor a certificate. HMAC cache (`AI_CACHE_HMAC_KEY`, 32+ chars) is off without a server secret, keyed by policy+task+provider+model+the tested credential/endpoint/upstream fingerprint+exact text and expires after seven days. No cache for learner personal data, quiz/feedback/coding or unpublished course credit. Plan approved retention deletion/audit and recovery before real records.

If `AI_GATEWAY_ENABLED` is false or migration absent, startup/routes stay closed. Pre-deploy must not silently turn on the existing combined public service.
6. In the admin UI set conservative **global USD estimate**, per-user attempts/tokens and *each provider's* daily attempts/tokens/USD; inspect the provider dashboard for native quota/spend caps. Add the exact documented **text** model ID, task capabilities, context/output limits, official model page and USD-per-million input/output rates; the record starts **disabled and unverified**. For NVIDIA see exact candidate `nvidia/nemotron-3.5-lightning-30b-a3b` (not an entitlement claim), with capability page on [due diligence](AI_PROVIDER_DUE_DILIGENCE.md). The adapter supports plain text `POST /v1/chat/completions` only; never configure the vision model for image/video here. Log a restricted terms decision reference (not a token) after owner review. This still does not mark it verified.
7. **Only after** a named owner approves a potentially charged **synthetic** real model call and checks accessible quota, set `AI_LIVE_TESTS_APPROVED=true` in that *private staging environment*, then click **Test live (may incur cost)** for a reviewed model. It sends a fixed fictional explanation to the configured provider, debits application budget, validates the real response, records health/usage and, only on success, records `verified_at`. The test is off by default. If no key/permission/valid output, status remains blocked; do not substitute a mocked test. Reset `AI_LIVE_TESTS_APPROVED=false` after evidence. **No such call was run for this source work.**
8. Enable a freshly verified model in that private synthetic environment, then set a task's primary and optional distinct fallback in the UI. The system supports explanation, lesson draft, coding help, quiz draft, feedback draft, learning-plan draft and translation draft. Approved model capability, not marketing labels, determines eligible routes. Request a fictional reviewer draft with a stable `requestId`; refresh/status error is not proof of success. A repeat **same ID and same input** returns only an existing saved draft; a pending/failed request returns 409 instead of silently spending again. Later enrolment or real learner data remains forbidden.

**Provider replacement:** verify new model's licence, terms, region, context/input/output/tool format, price, credential and live response; register **disabled** model with fresh decision reference; set restrictive provider cap and test health/quality/fallback; enable, switch one task route in UI, monitor error/cost/teaching quality, disable old model, revoke unused secret. Cache is vendor/model/policy/**tested configuration** scoped, so old cached content is not reused on replacement or credential/endpoint/upstream rotation even after a fresh real verification; the rotation also makes previously enabled routes ineligible until retested. Ollama model-tag replacement under the same name also needs an operator-enforced re-verification and digest check (not automated). Never make a paid fallback from an assumed-free plan without a separate budget approval. PostgreSQL route writes are audited; the frontend never needs a provider-specific change.

## Failure, privacy and release gates

- **No credential, term decision, allowance, migration or enabled task route:** routes deny or return explicit unavailable/quota; no fictitious completion. **Provider 429 / upstream error:** attempt and cooldown recorded, bounded retry if safe/budgeted, then separate approved fallback; otherwise unavailable. **Malformed/refusal/truncated/unsafe response or operator disablement/re-route/permission revocation during an in-flight call:** no draft or course write; do not claim success. **Database unavailable:** operation unconfirmed; inspect request ID before any new attempt. **Incident:** disable model/gateway in private config, revoke compromised key, preserve metadata only, consult privacy/safeguarding owner; no key/log dumps or unreviewed fallback.
- Admin health is **last observed**, not an automated free health probe; active probes can incur costs. Account/billing dashboards remain authoritative for vendor quotas and charges. A simulated fetch test or green build does **not** mark provider operational.
- Before real adult or child access: verified identity + reviewer MFA, Ghana legal/DPC and vendor DPA/transfers/retention, provider commercial and age terms, budget sign-off, monitoring and paid-limit guardrails, application-level moderation/human escalation, manual representative-user and WCAG 2.2 AA AT review, penetration/privacy assessment, provider-credential integration, safe retention/erasure, backups+isolated restore, publication/versioning policy and incident exercises. Under-18 access also requires all SAF-01 gates, not a feature flag. **FND-01 and AI-01 remain pending/blocked as recorded in the authoritative register.**
