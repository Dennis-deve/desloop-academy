## Proposed studio boundary — external editor research, not this local persistence API

[REA Phase 1](REA_PHASE1_STUDIO_RESEARCH.md) inspected bounded source at pinned SHAs; [Phase 2](REA_PHASE2_STUDIO_FEASIBILITY.md) verified a genuine current Scratch standalone editor **in an isolated one-shot lab harness** and an anonymous **unsaved** GDevelop hosted editor/blank-scene preview under bounded throttling. These external probes are **not** Desloop modules. The observed GDevelop preview shared the **editor origin and root-scoped controlling service worker**; a future learner-authored runtime cannot simply share the authenticated academy origin/cookies. A separately authorised adult-only editor needs reviewed editor/preview origin segregation, CSP/worker behavior, server-owned project identity/object access/immutable revisions, evidence/rubric verification and explicit conflict/offline recovery. The new **local** `project_core.projects` migration/API and a separate data-only JSON client provide account-owned persistence and browser conflict/retry, **not** a licensed block/code editor, classes/tenant model, Supabase account, runtime/preview sandbox or export endpoint. Scratch's AGPL/trademark, GDevelop's MIT/asset/service terms, Ghana low-RAM proof and any Next.js/Supabase migration are open gates. An iframe or V8 heap flag is neither a legal nor a privacy/device-memory boundary. The one ordered 44-course progression remains authoritative; child release flags remain false.

## Database and server invariants

Migrations are additive: 001 `pilot.*` adult users/invitations/sessions/attempts/reviews/audit; 002 `learning.*` candidate releases, lessons, progress/revisions/reviews; 003 safeguarding controls; **004 `ai.*` and 005 `project_core.*` are both optional and absent from automatic Railway pre-deploy**. Existing startup verifies release hashes, policies and disabled child gate; AI startup verifies provider settings if separately enabled, and local project-core startup verifies source checksum and enabled schema/immutability protections if independently enabled. Project core additionally refuses production/remote or non-disposable DB configuration before startup. A failed pre-deploy migration blocks the new app. PostgreSQL transactions and row locks serialise learning decisions; URL changes and client scores have no authority. Database owner can alter application-owned audit logs; independent retention, restricted roles and review are still required. The full [data model](DATA_MODEL.md) and [permission matrix](ROLES_AND_PERMISSIONS.md) separate this partial adult boundary from future tenant/child/payment systems.

## Missing integrations and safety boundaries

**AI-01 exists as a default-off source boundary and locally tested synthetic pilot, not a live or operational provider service.** Billing, partner attribution, school tenancy, notifications, **general/deployed** uploads, unrestricted community, desktop sync, verified identity and guardian consent **do not exist as live services**. The separate bounded PNG intake is only a named-disposable local adult API, not an upload provider or real-user approval. Their older browser mockups are not release routes. Implement provider-neutral server boundaries with configuration, scopes, idempotency and tests in later feature IDs; never make frontend role switching or localStorage authoritative. Public assets and HTML must not include secret assessment keys. Before an adult browser pilot, require approved identity-aware same-origin HTTPS access, MFA for reviewers, backups/restore, rate-limit design, content/accessibility/privacy review. Before minors, complete [the child release hold](GUARDIAN_CONSENT_AND_IDENTITY.md) with qualified Ghana-first advice and trained operations. No claim of WCAG, security or legal compliance follows merely from this architecture.
