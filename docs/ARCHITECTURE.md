# Architecture, boundaries and module dependency map

**Working branch status (22 October 2026):** The existing React/TypeScript + Fastify/TypeScript + PostgreSQL system was inspected, not replaced. FND-01 is a **local, unpushed** no-demo release candidate. GitHub `main`/domainless Railway still run the previously verified adult/internal draft build until a newly authorised push and deployment check. No public or minor release is authorised.

## Runtime paths

```text
READ-ONLY RELEASE: React main.tsx → ReleaseRouter/ReleaseLayout → ReleasePages
  → public-catalog.json (generated by strict allowlist from master.json)
  → search/stage filter/detail/availability UI; NO enrolment or persisted visitor state.
  → Fastify static fallback returns 404 for discontinued/unknown routes; generated public/_redirects has only 48 exact informational SPA paths (no wildcard).

PRIVATE ADULT PILOT (unchanged authority): React /pilot/* → same-origin /api/pilot/*
  → Fastify authentication/CSRF/role checks → PostgreSQL pilot.* and learning.*
  → only server-approved draft progress/review; no browser role switch.

HARD CHILD HOLD: loadConfig rejects all truthy minor flags; safeguarding.release_gate
  CHECK constraints keep child account/data/learning fields false; 8 controls not_ready.
```

The historical `src/app/router.tsx`, `src/app/providers.tsx`, `src/services/demo.ts` and preview feature modules are **not imported by `main.tsx` or the new release graph**. They remain in source/Git history to avoid silently destroying earlier work; archived browser-only tests are not product evidence. The release verifier checks the built JavaScript graph and refuses known fake-workspace signatures and assessment question text. No second app, Supabase fork or Electron wrapper was introduced.

## Database and server invariants

Migrations are additive: 001 `pilot.*` adult users/invitations/sessions/attempts/reviews/audit; 002 `learning.*` candidate releases, lessons, progress/revisions/reviews; 003 safeguarding controls. Startup verifies release hashes, policies and disabled child gate; a failed pre-deploy migration blocks the new app. PostgreSQL transactions and row locks serialise learning decisions; URL changes and client scores have no authority. Database owner can alter application-owned audit logs; independent retention, restricted roles and review are still required. The full [data model](DATA_MODEL.md) and [permission matrix](ROLES_AND_PERMISSIONS.md) separate this partial adult boundary from future tenant/child/payment systems.

## Missing integrations and safety boundaries

AI, billing, partner attribution, school tenancy, notifications, uploads, unrestricted community, desktop sync, verified identity and guardian consent **do not exist as live services**. Their older browser mockups are not release routes. Implement provider-neutral server boundaries with configuration, scopes, idempotency and tests in later feature IDs; never make frontend role switching or localStorage authoritative. Public assets and HTML must not include secret assessment keys. Before an adult browser pilot, require approved identity-aware same-origin HTTPS access, MFA for reviewers, backups/restore, rate-limit design, content/accessibility/privacy review. Before minors, complete [the child release hold](GUARDIAN_CONSENT_AND_IDENTITY.md) with qualified Ghana-first advice and trained operations. No claim of WCAG, security or legal compliance follows merely from this architecture.
