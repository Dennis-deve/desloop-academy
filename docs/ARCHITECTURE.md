The historical `src/app/router.tsx`, `src/app/providers.tsx`, `src/services/demo.ts` and preview feature modules are **not imported by `main.tsx` or the new release graph**. They remain in source/Git history to avoid silently destroying earlier work; archived browser-only tests are not product evidence. The release verifier checks the built JavaScript graph and refuses known fake-workspace signatures and assessment question text. No second app, Supabase fork or Electron wrapper was introduced.

## Database and server invariants

Migrations are additive: 001 `pilot.*` adult users/invitations/sessions/attempts/reviews/audit; 002 `learning.*` candidate releases, lessons, progress/revisions/reviews; 003 safeguarding controls; **004 `ai.*` is optional, private and not in the automatic Railway pre-deploy path**. Existing startup verifies release hashes, policies and disabled child gate; AI startup also verifies settings when deliberately enabled and fails closed without 004. A failed pre-deploy migration blocks the new app. PostgreSQL transactions and row locks serialise learning decisions; URL changes and client scores have no authority. Database owner can alter application-owned audit logs; independent retention, restricted roles and review are still required. The full [data model](DATA_MODEL.md) and [permission matrix](ROLES_AND_PERMISSIONS.md) separate this partial adult boundary from future tenant/child/payment systems.

## Missing integrations and safety boundaries

**AI-01 exists as a default-off source boundary and locally tested synthetic pilot, not a live or operational provider service.** Billing, partner attribution, school tenancy, notifications, uploads, unrestricted community, desktop sync, verified identity and guardian consent **do not exist as live services**. Their older browser mockups are not release routes. Implement provider-neutral server boundaries with configuration, scopes, idempotency and tests in later feature IDs; never make frontend role switching or localStorage authoritative. Public assets and HTML must not include secret assessment keys. Before an adult browser pilot, require approved identity-aware same-origin HTTPS access, MFA for reviewers, backups/restore, rate-limit design, content/accessibility/privacy review. Before minors, complete [the child release hold](GUARDIAN_CONSENT_AND_IDENTITY.md) with qualified Ghana-first advice and trained operations. No claim of WCAG, security or legal compliance follows merely from this architecture.
