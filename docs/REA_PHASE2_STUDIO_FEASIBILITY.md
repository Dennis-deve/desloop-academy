# Studio Phase 2 — licences, genuine editor probes and low-bandwidth constraints

**31 October 2026 · Completed research experiment, not an implementation or legal sign-off.** The owner authorised **research only** after [Phase 1 static REA/source analysis](REA_PHASE1_STUDIO_RESEARCH.md). This study used fresh anonymous browser contexts and a one-shot isolated local harness; it did **not** add any editor dependency, API, migration, save button, project, container, child access, payment, provider key or public surface to Desloop. All changes for this report are documentation/research evidence, local only. The live [read-only 44-course guide](https://desloop-readonly-guide.onrender.com), existing React/Vite/Fastify/PostgreSQL system, private adult/API boundary and disabled minors/AI remain unchanged.

## Decision summary

- **An actual editor was observed for each candidate.** The current Scratch Foundation **`@scratch/scratch-gui@15.3.0`** standalone UMD bundle loaded a built-in Stage and Sprite1, Blockly workspace and a working green-flag → VM `PROJECT_START` event **without outside browser requests** in a one-shot loopback harness. GDevelop's **vendor-hosted, logged-out** editor created a genuine **unsaved** empty scene/events sheet; clicking Preview opened a same-origin service-worker-controlled GDJS page with a 1280×720 WebGL2 canvas. Neither is a Desloop feature, hosted private studio or durable project round-trip. [Scratch observations](evidence/rea-phase2/results/scratch-standalone-baseline.json), [GDevelop editor](evidence/rea-phase2/results/gdevelop-empty-baseline.json), [preview](evidence/rea-phase2/results/gdevelop-preview-baseline.json).
- **Both were slow in the bounded 0.8-Mbps/4×-CPU lab profile:** ~**65.4 s** to Scratch's built-in project and ~**47.3 s** to GDevelop's empty scene, one run each. This is a constraint/risk signal, **not** a Ghana device/ISP pass or a head-to-head product benchmark. Their deployments and content are different; GDevelop's slow run transferred less promotional/background material than baseline. [Scratch slow](evidence/rea-phase2/results/scratch-standalone-slow.json), [GDevelop slow](evidence/rea-phase2/results/gdevelop-empty-slow.json).
- **Licences do not equal deployment approval.** Current Scratch GUI and VM packages declare **AGPL-3.0-only**, with separate Scratch trademark restrictions; the current GUI's React 18 peers match Desloop's React 18 major, unlike the **archived** Scratch GUI pin used for Phase 1. GDevelop's pinned Core/GDJS/GDevelop.js/**IDE** texts are MIT and its README explicitly reserves its name/logo. MIT source rights do **not** grant the separately operated GDevelop cloud, build, AI, brand or premium-asset services. A qualified legal/IP and distribution review must precede any Desloop incorporation. [Current Scratch GUI package](https://github.com/scratchfoundation/scratch-editor/blob/478149ee07f7f5156defe6f239f776b1c6ccbcae/packages/scratch-gui/package.json#L10-L15), [VM package](https://github.com/scratchfoundation/scratch-editor/blob/478149ee07f7f5156defe6f239f776b1c6ccbcae/packages/scratch-vm/package.json), [GDevelop licence summary](https://github.com/4ian/GDevelop/blob/85ab0e40e00fdc775e22e014fb885d2390705827/README.md#L64-L69).
- **Recommended research direction, not consent to build:** Keep the existing stack and course authority. Consider a **legally reviewed, self-hosted GDevelop-derived adult-only game editor** as the lower-*copyleft*-risk candidate, **if** its heavy startup, tracking/service dependencies, project storage and preview isolation can be addressed. Keep Scratch as a conditional blocks option only after the owner and qualified counsel resolve AGPL/source-offer and brand choices. Neither supports the six requested tracks, minors, teacher classes, automatic credit, offline sync or the asserted $5/student hosting economics by itself. `STU-01` remains `BLOCKED_DECISION`; `RES-REA-01` remains `IN_PROGRESS` pending full third-party review and representative testing.

**What the low-memory probe really says:** each *empty/default* editor survived a **V8 old-space** cap in this laboratory; this cannot establish operation on 1 GB or 2 GB Ghana Android phones. Even Scratch's baseline Chromium **~350 MiB PSS** and hosted GDevelop's **~829 MiB PSS** are headless x86_64, software-rendered, snapshot-specific process accounting, not mobile/peak measures. A warm/cold, repeated real-device matrix with realistic projects, WebGL/GPU memory, crashes, throttling, battery, offline/reconnect, keyboard/touch and screen readers is a prerequisite for claiming the 3G/low-RAM target. Define an owner-approved acceptable time-to-usable threshold **before** optimizing or claiming success. There has been **no WCAG 2.2 AA manual sign-off**.

## Integration/security implications — proposed design only

1. **Preserve authority and scope.** The current branded 44-course ordered/versioned curriculum, private adult identity, PostgreSQL progression and Railway selection remain authoritative. An editor cannot write XP, grades, completion or teacher feedback from client assertions. Next.js/Supabase/Prisma is **not** an approved migration; source-study tests have not touched it. Model one adult/internal game project and a versioned lesson/rubric contract before expanding tracks or age bands.
2. **Separate origins before trying an authenticated project.** GDevelop's running preview was **service-worker-controlled at the editor root scope**, and the [pinned source](https://github.com/4ian/GDevelop/blob/85ab0e40e00fdc775e22e014fb885d2390705827/newIDE/app/src/ExportAndShare/BrowserExporters/BrowserSWPreviewLauncher/BrowserSWPreviewIndexedDB.js#L46-L64) generates same-origin preview files. Since GDevelop also supports [inline JavaScript events](https://github.com/4ian/GDevelop/blob/85ab0e40e00fdc775e22e014fb885d2390705827/newIDE/app/src/EventsSheet/EventsTree/Renderers/JsCodeEvent.js#L294-L317), a future learner-authored preview must **not** share a cookie/local-storage/service-worker origin with the authenticated academy. A reviewed design needs distinct no-credential editor/preview origins, narrow worker scope or alternative export pipeline, CSP/frame/COOP/COEP as applicable, asset/CORS isolation and an adversarial origin/worker/same-site cookie test. Whether the unmodified GDevelop editor can meet this without substantial change remains **unproven**; an iframe alone is insufficient.
3. **Replace vendor project authority rather than relabelling it.** Scratch's standalone API worked only on `projectId:'0'` with `canSave:false`, and GDevelop's test explicitly chose **Don't save**. No Desloop storage or provider was tested. A future adapter must bind Desloop session/owner/tenant/lesson to server-checked immutable revision IDs, asset digests, quotas and idempotent optimistic writes; show pending/failed/conflict/retry honestly; test export→reopen→preview and independent artifact checks, not just successful UI click. Neither hosted GDevelop's accounts/credits nor Scratch storage/cookies become Desloop authority.
4. **Keep a narrow abuse/safeguarding perimeter.** Review Scratch extension/device APIs, GDevelop JavaScript events/WebGL, media/ZIP uploads, arbitrary code, offline/shared-device drafts, accessibility and resource consumption. Block arbitrary browser terminals, cyber containers, public arcade/gallery, AI and school/minor flows pending **separate** accepted feature IDs and qualified safety/legal/privacy and staff/tenant reviews. No paid build worker or per-user container is authorised by these browser observations.
5. **Quantify the next decision.** Require owner-selected budget/latency thresholds and test **real 1 GB/2 GB Android devices on Ghana-relevant links** (including warm/cold and offline reconnect), representative projects, keyboard/AT/mobile and accessibility, true origin/tenant abuse, right-to-use/brand and measured infrastructure/provider costs. A small private research benchmark is not evidence that low-RAM devices, large projects or school networks will work.

## Open owner/counsel gates; no automatic Phase 3

1. **Licence/brand:** Is Desloop willing to comply with a counsel-approved AGPL/source-offer plan for Scratch integration, or should only MIT-licensed *self-hosted, dependency-audited* GDevelop be investigated further? Who signs off trademark/asset/third-party and Ghana child/privacy terms?
2. **Architecture and paid infrastructure:** Retain the existing React/Vite/Fastify/Railway PostgreSQL backbone for a **later** adult-only, owner-isolated studio adapter, or separately authorise and test a specific migration? An isolated editor/preview hostname and any hosting/build costs require an owner decision and budget; this report does **not** order infrastructure.
3. **Acceptance thresholds and future feature scope:** Approve time-to-usable and RAM ceilings, representative projects/devices and a legal/safety-reviewed adult/internal test population before any `STU-01` implementation. Decide one real project format and save/round-trip tests before UI claims. Child release remains governed by `SAF-01` independently.

**No production QA was run in Phase 2 because the application was not changed.** Research JSON/manifest/path validation and documentation diff checks are recorded in the local-only worktree. No GitHub push, Render/Railway deploy, Desloop runtime request, account login or downstream client dependency was performed.
